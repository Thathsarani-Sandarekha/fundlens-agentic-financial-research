# Retrieval optimization experiment (27 October 2026)

## Question

Would removing generic AI competition/infrastructure query expansion, particularly from Hybrid narrative retrieval, improve relevance in the top five passages?

## Method

- Five RAG/Hybrid Alphabet questions; five retrieved passages per query.
- Candidate **focused query** versus the existing **original query**.
- Initially inconsistent Groq judgments: identical passages received different relevance grades.
- Corrected with a **single relevance judgment per unique passage per question**, reused consistently across both retrieval methods. A grade >=2 on a 0–3 scale counted as relevant.

## Corrected offline results

| Question | Original Precision@5 | Focused Precision@5 |
|---|---:|---:|
| General AI risks | 60% | 40% |
| FY2024 revenue + AI risks | 80% | 100% |
| AI infrastructure / investment / patents | 60% | 40% |
| AI liability / privacy / cybersecurity | 80% | 100% |
| FY2024 net income + AI risks | 80% | 100% |
| **Five-question aggregate** | **72% (18/25)** | **76% (19/25)** |

- MRR@5: 0.80 original; 0.90 focused.
- nDCG@5: approximately 0.824 original; 0.908 focused.
- Using original retrieval for pure-RAG and focused retrieval only for Hybrid produced an **estimated 80%** Precision@5 on this offline set. This was a **what-if estimate**, not a measured stable production score.

### Why this does not replace the 44% headline score

The prior 44% (11/25) was generated by a **separate five-question LLM-judge run**, with different judged results. The change from 44% to a 72% baseline in the fair review does **not** indicate the retriever improved between runs. Cross-run judge variability is a limitation.

## Live regression and rollback

The Hybrid-only query experiment subsequently achieved **5/10 automatic passes**, down from an earlier 10/10 stable run. The regression included a FY2024 request returning a **2025 Q1 10-Q** chunk in the retrieved evidence and multiple unsuccessful SQL/RAG operations. The precise cause of all LLM failures could not be established from the result JSON, so those failures should not all be attributed to query rewriting.

**Decision: reject experimental patch.** Restoring the earlier strict-metadata implementation yielded a successful **5/5 core smoke test**: routing and exact financial results passed, RAG and Hybrid completed, and retrieved narrative evidence came from FY2024 10-K Risk Factors. This smoke test did **not** include a fresh LLM-judged Precision@5 calculation.

## Lessons

- Improving an offline retrieval metric is insufficient if end-to-end reliability or document filtering regresses.
- LLM-judged retrieval metrics should have calibrated, consistent labels for shared chunks.
- Hybrid questions should independently enforce ticker, filing type, reporting period and section requirements.
- Future work: better reranking and source filtering, with additional test questions beyond one company.
